# Build Plan: Prusa Buddy3D Camera Impersonator on Raspberry Pi Zero 2 W

## Target Hardware
- Raspberry Pi Zero 2 W (quad A53, 512MB, WiFi)
- Raspberry Pi Camera (connected, CSI)
- Raspberry Pi OS Lite 64-bit (fresh install, latest update)
- SSH: `pi@<PI_IP>` (no password)

## Architecture
Single Python process using GStreamer (HW-accelerated) for video and asyncio for protocol.

## Reference Files
- `../protocol.md` — definitive protocol spec (field numbers, events, wire format)
- `../implementation.md` — code examples, constants, protobuf encoding

## Phase 1: Snapshot Camera (HTTP only, no Socket.IO)

Goal: Camera appears in Prusa Connect with updating snapshots. Simplest possible path.

- [x] **1.1** Create `~/prusa-cam/config.ini`
  ```ini
  [identity]
  token = <USER MUST PASTE FROM PRUSA CONNECT>
  fingerprint = <auto-generated on first run>

  [camera]
  width = 1920
  height = 1080

  [upload]
  interval = 10
  server = webcam.connect.prusa3d.com
  ```
  **Note:** User must get token from Prusa Connect web UI: add a camera, copy the token.

- [x] **1.2** Create `~/prusa-cam/proto.py` — Protobuf encoder
  ```
  Functions:
  - encode_varint(value) -> bytes
  - encode_string_field(field_number, value) -> bytes
  - encode_uint_field(field_number, value) -> bytes
  - encode_message(fields: dict) -> bytes
  ```
  **Verify:** `encode_message({1: "hello", 2: "world"})` produces valid protobuf bytes `0a 05 68656c6c6f 12 05 776f726c64`

- [x] **1.3** Create `~/prusa-cam/camera.py` — JPEG capture
  ```
  Functions:
  - capture_jpeg(width, height) -> bytes
    Uses rpicam-jpeg subprocess (most reliable on Pi)
    Returns JPEG binary
  ```
  **Verify:** `capture_jpeg(1920, 1080)` returns bytes starting with `ff d8`

- [x] **1.4** Create `~/prusa-cam/upload.py` — HTTP snapshot uploader
  ```
  Functions:
  - async upload_snapshot(jpeg_bytes, token, fingerprint, server) -> int (status code)
  
  Headers:
    User-Agent: Buddy3D Camera
    Token: <token>
    Fingerprint: <fingerprint>
    Content-Type: image/jpg
  
  Method: PUT /c/snapshot
  ```
  **Verify:** Returns 200 or 204 (success) — camera snapshot visible in Prusa Connect

- [x] **1.5** Create `~/prusa-cam/main.py` — Entry point for Phase 1
  ```
  Loop:
    1. Load config
    2. Generate fingerprint if not set (MD5 of Pi serial from /proc/cpuinfo)
    3. Capture JPEG
    4. Upload to Prusa Connect
    5. Sleep interval
    6. Repeat
  ```
  **Verify:** Run manually, see snapshots updating in Prusa Connect web UI

- [x] **1.6** Create systemd service `prusa-cam.service`
  ```ini
  [Unit]
  Description=Prusa Camera Impersonator
  After=network-online.target
  Wants=network-online.target

  [Service]
  Type=simple
  User=pi
  WorkingDirectory=/home/pi/prusa-cam
  ExecStart=/home/pi/prusa-cam/venv/bin/python main.py
  Restart=always
  RestartSec=5

  [Install]
  WantedBy=multi-user.target
  ```
  **Verify:** `sudo systemctl start prusa-cam && journalctl -u prusa-cam -f` shows uploads succeeding

## Phase 2: Socket.IO Signaling (Full Impersonation)

Goal: Camera authenticates via Socket.IO, sends status/features, appears as "online" with full capabilities.

- [x] **2.1** Create `~/prusa-cam/signaling.py` — Socket.IO client
  ```
  Class PrusaSignaling:
    - connect() -> connects to wss://camera-signaling.prusa3d.com
    - authenticate(fingerprint, token) -> emits "camera_authentication", waits ACK
    - send_status(camera_info) -> emits "status" protobuf
    - send_version(fingerprint) -> emits "protobuf_version" with "4.4"
    - send_features(features_string) -> emits "features" protobuf
    - on_trigger(handler) -> registers trigger event callback
    - on_webrtc(handler) -> registers webrtc event callback
    - on_config(handler) -> registers config event callback
  ```
  **Verify:** Auth succeeds (ACK "OK" in logs), camera shows "online" in Prusa Connect

- [x] **2.2** Create `~/prusa-cam/features.py` — Constants
  ```python
  PROTOCOL_VERSION = "4.4"

  MODEL = "Niceboy"
  MANUFACTURER = "Niceboy"
  USER_AGENT = "Buddy3D Camera"
  TRIGGER_SCHEME = "THIRTY_SEC"
  
  FEATURES = (
      '"SocketCom","UploadInterval","TimelapseEn","TimelapseInterval",'
      '"TimelapseVideoMake","TimelapseFileList","VideoStream","RtspStream",'
      '"GetSnapshot","IrMode","SpeakerVolume","WiFi","FwVer","HwVer",'
      '"CameraName","MicroSd","FwUpdate","CameraReboot","McuTemp",'
      '"VideoQuality","WebRtc","TurnVideoQualityChange","trigger_scheme","FanControl"'
  )
  ```

- [x] **2.3** Update `main.py` with full connection flow
  ```
  1. Load config
  2. Generate fingerprint
  3. Connect Socket.IO
  4. Authenticate (emit "camera_authentication")
  5. Send status (emit "status")
  6. Send version (emit "protobuf_version" with "4.4")
  7. Send features (emit "features")
  8. Start snapshot upload loop in background
  9. Handle incoming events (triggers, config)
  10. Reconnect on disconnect
  ```
  **Verify:**
  - ACK "OK" received after auth
  - Camera shows online in Prusa Connect
  - Camera name/model visible in UI
  - Snapshots continue uploading

- [x] **2.4** Handle trigger events
  ```
  On "get_snapshot": capture + upload immediately
  On "get_features": re-send features
  On "get_status": re-send status
  Others: log and ignore
  ```
  **Verify:** Click "Take snapshot" in Prusa Connect → new snapshot appears

## Phase 3: WebRTC Live Streaming

Goal: "Watch live" button in Prusa Connect shows real-time video from the Pi camera.

- [x] **3.1** Create `~/prusa-cam/webrtc.py` — GStreamer WebRTC bridge
  ```
  Class PrusaWebRTC:
    - create_pipeline() -> GStreamer pipeline with webrtcbin
    - handle_offer(request_id, sdp) -> set remote SDP, create answer
    - on_answer_created(sdp) -> callback to send answer via signaling
    - on_ice_candidate(candidate) -> callback to send candidate via signaling
    - stop() -> tear down pipeline

  GStreamer pipeline:
    libcamerasrc ! video/x-raw,width=1920,height=1080,framerate=30/1
    ! v4l2h264enc extra-controls="controls,repeat_sequence_header=1"
    ! h264parse config-interval=-1
    ! rtph264pay config-interval=1 pt=96
    ! webrtcbin name=webrtc
  ```
  **Verify:** Pipeline starts without error (test with `GST_DEBUG=3`)

- [x] **3.2** Wire signaling to webrtcbin
  ```python
  @signaling.on_webrtc
  async def handle_webrtc(data):
      msg = decode_protobuf(data)
      request_id, msg_type, sdp = msg[1], msg[2], msg[3]
      
      if msg_type == "offer":
          answer_sdp = webrtc.handle_offer(request_id, sdp)
          await signaling.emit('webrtc', encode_message({
              1: request_id,
              2: "answer",
              3: answer_sdp,
          }))
      elif msg_type == "candidate":
          webrtc.add_ice_candidate(sdp)
  
  webrtc.on_ice_candidate = lambda candidate: signaling.emit('webrtc', encode_message({
      1: request_id,
      2: "candidate",
      3: candidate,
  }))
  ```
  **Verify:** Click "Watch live" in Prusa Connect → video stream appears

- [ ] **3.3** Handle ICE/STUN/TURN from incoming offer
  ```
  Parse STUN/TURN servers from incoming WebRTC protobuf fields 4-9
  Configure webrtcbin with received ICE servers
  Fall back to defaults: stun:stun.l.google.com:19302
  ```
  **Verify:** Stream works both on LAN and remote (via TURN)

- [ ] **3.4** Handle video quality changes
  ```
  On video quality config event (1=SD, 2=HD, 3=FHD):
    Rebuild GStreamer pipeline with new resolution
  ```
  **Verify:** Change quality in Prusa Connect → stream resolution changes

## Token Acquisition (User Action Required)

1. Go to https://connect.prusa3d.com
2. Navigate to Cameras
3. Click "Add Camera" (or "Add another camera")
4. Copy the token shown
5. Paste into `config.ini` as `token = <value>`

This is the ONLY manual step — everything else is automated.

## Risks and Fallbacks

| Risk | Mitigation |
|------|-----------|
| `v4l2h264enc` not available on Pi OS Lite | Use `rpicam-vid --codec h264 -o -` piped to GStreamer `fdsrc` |
| `webrtcbin` not packaged | Install `gstreamer1.0-plugins-bad` (includes webrtcbin) |
| aiortc needed as WebRTC fallback | `pip install aiortc` — works but higher CPU |
| 512MB RAM tight with GStreamer + Python | Monitor with `free -h`; reduce resolution if needed |
| Prusa rejects our auth | Check token is correct; try snapshot-only first (no socket.io needed) |
| Server expects unknown protobuf fields | Send minimal message; iterate based on ACK error strings |
